# YOSHI Health Tracker

①健康 ②筋肉トレーニング ③体重を上げる ― この3つを目標に、食事・トレーニング・体重を一元管理する
ブラウザ完結型の記録アプリです。サーバーやビルド不要、`index.html` を開くだけで使えます。

## 使い方

1. `index.html` をブラウザで開く(ホーム画面への追加方法は下記「スマホにインストール」を参照)
2. 「設定」タブで身長・年齢・性別・活動レベル・増量目標を入力して保存
3. 「体重」タブで今日の体重を記録(初回は必須。以後は毎日〜数日おきに記録)
4. 「食事」タブで食べたものを記録(写真は記録用として添付可能、栄養は手入力)
5. 「筋トレ」タブで種目(胸/背中/脚/肩/腕/体幹の基礎種目から選択、リストにない種目は
   「＋ その他(自由入力)」から入力可能)・セット数・重量を記録
6. 「今日」タブでカロリー・たんぱく質・脂質・炭水化物の目標に対する達成率を確認
7. 「傾向」タブで、選んだ期間(1週間/1ヶ月/3ヶ月/全期間)の平均達成率・体重の増減ペース・
   トレーニング頻度と、そこから導いた「気づき」コメントを確認

## 目標値の計算方法

- 基礎代謝(BMR): Mifflin-St Jeor式
- 消費カロリー(TDEE) = BMR × 活動レベル係数
- 摂取目標カロリー = TDEE + 増量分の上乗せカロリー(設定タブで調整、デフォルト +400kcal)
- **たんぱく質目標 = 体重(kg) × 2g**(指定どおり)
- 脂質目標 = 摂取目標カロリー × 設定した割合(デフォルト25%) ÷ 9
- 炭水化物目標 = 残りのカロリーから算出

体重を記録するたびに基準体重が更新され、目標値も自動的に再計算されます。

## 傾向タブ(ルールベース分析)

外部AIやサーバーを使わず、記録データから機械的に集計・判定して「気づき」を表示します。

- 平均カロリー/たんぱく質達成率: 選んだ期間内で食事を記録した日について、その日時点の
  体重をもとに計算した目標(BMR→TDEE→摂取目標カロリー、たんぱく質=体重×2g)と実際の
  摂取量を比較した平均
- 体重ペース: 期間内で最初と最後の体重記録の差を、週あたりに換算(2件未満なら「記録不足」)
- トレーニング日数: 期間内でトレーニングを1件でも記録した日数
- 気づきコメント: 上記の数値をしきい値判定して自動生成(例: カロリー90%未満→不足を指摘、
  体重ペース週+0.1〜0.5kg→良いペースと評価、など)。将来的にAIによる自然文アドバイスに
  発展させる余地を残した設計です

## データの保存場所

すべてのデータ(プロフィール・食事記録・トレーニング記録・体重記録・写真)は、
このアプリを開いているブラウザの `localStorage` にのみ保存されます。
外部サーバーへの送信は一切行いません。

- 機種変更・ブラウザ変更の前には「設定」タブの **JSONをエクスポート** で必ずバックアップしてください
- 別の端末やブラウザで使う場合は、エクスポートしたJSONを **JSONをインポート** で読み込んでください、
  または下記の「他の端末と同期」を設定すると自動化できます
- ブラウザのキャッシュ削除・シークレットモードではデータが失われるので注意してください

## 他の端末と同期(Google Drive、任意)

PC・iPhoneなど複数の端末で同じ記録を使いたい場合、Googleアカウントでログインすると
Google Driveの「アプリ専用フォルダ」(このアプリからしか読み書きできない、あなたの
Drive上の他のファイルからは独立した領域)経由で自動同期できます。設定しなくても
アプリ自体は今まで通り使えます。

### セットアップ(最初に1回だけ・所要5分程度)

1. https://console.cloud.google.com/ にアクセスし、新しいプロジェクトを作成
   (例:「YOSHI Health Tracker」)
2. 左メニュー「APIとサービス」→「ライブラリ」で **Google Drive API** を検索して有効化
3. 「APIとサービス」→「OAuth同意画面」
   - User Type: **外部(External)**
   - アプリ名: 任意(例:「健康トラッカー」)、サポートメール: 自分のGmailアドレス
   - 「テストユーザー」に自分のGmailアドレスを追加(これで審査不要のまま自分だけ使えます)
4. 「APIとサービス」→「認証情報」→「+ 認証情報を作成」→「OAuthクライアントID」
   - アプリケーションの種類: **ウェブアプリケーション**
   - 「承認済みのJavaScript生成元」に `https://yoshi933549.github.io` を追加
   - 作成後に表示される **クライアントID**(`xxxxx.apps.googleusercontent.com` の形式)をコピー
5. `js/sync.js` の先頭にある `GOOGLE_CLIENT_ID` を、コピーしたクライアントIDに置き換えて保存・デプロイ

設定が完了すると、「設定」タブの「他の端末と同期」に「Googleでログインして同期」ボタンが
表示されます。ログインすると、記録するたびに自動でGoogle Driveへ保存され、他の端末で
開いたときに新しい方(タイムスタンプ比較)が自動的に反映されます。

### 制限事項

- 複雑な自動マージは行わず、「最後に保存した方が勝つ」単純な方式です。2台で同時に別々の
  記録を追加した場合、後から同期した方の内容で上書きされます(通常の使い方では起きにくい想定です)
- iPhoneのSafariはプライバシー保護機能により、ログインしたままでも自動更新が効かないことが
  あります。その場合は「設定」タブの「今すぐ同期」を1回タップしてください
- クライアントIDは公開情報として扱われます(client secretではないので、コードに直接
  書いても問題ありません)が、OAuth同意画面を「本番公開」しない限り、テストユーザーに
  登録したアカウント以外はログインできません

## 体重計との自動連携(iPhone ヘルスケア → n8n、任意)

Apple Healthに同期する体重計(RENPHO・Withings・Eufyなど)を使っている場合、
n8n経由でこのアプリに体重を自動的に取り込めます。

### 仕組み

1. 体重計のメーカーアプリがBluetoothで測定値を受信し、Apple Healthに記録
2. iPhoneの「ショートカット」で自動化を1つ作成(例: 毎朝8時)
   → 「ヘルスケアのサンプルを検索」(体重・最新1件)→ n8nのWebhookにPOST送信
3. n8n(`YOSHI 体重同期` ワークフロー、Data Table `yoshi_weight_log` に保存)が受け取って保存
4. このアプリが別のWebhook(GET)を定期的に取得し、まだ記録されていない日付だけを
   体重ログに追加(「隙間埋め」方式。アプリ内で手入力・編集した記録は上書きしません)

n8n側のWebhook URLには秘密のトークンが含まれるため、**リポジトリのコードには一切含めず**、
「設定」タブの「体重計と自動連携」欄にご自身で貼り付けてブラウザ内(localStorage)にのみ
保存する設計です。

### セットアップ

1. 「設定」タブの「体重計と自動連携」に、n8nから発行された**取得用URL**(GET、
   `.../webhook/yoshi-weight-out?token=...`)を貼り付けて保存
2. iPhoneの「ショートカット」アプリで自動化を作成:
   - オートメーション → 時刻(毎朝など)
   - 「ヘルスケアのサンプルを検索」→ 種類: 体重、並べ替え: 新しい順、上限: 1件
   - 「URLの内容を取得」→ **投稿用URL**(POST、`.../webhook/yoshi-weight-in`)に、
     JSON本文 `{"date": "<今日の日付>", "weight": <取得した体重>, "token": "<秘密のトークン>"}` を送信

投稿用URL・取得用URL・トークンは、このアプリの管理者(n8nワークフローの所有者)が発行します。

## 写真について

食事の写真はその場でブラウザ内で自動リサイズ(最大480px・JPEG圧縮)してから保存されるため、
現状は記録・見返し用の添付画像としてのみ利用します(自動での栄養解析は行いません)。
カロリー・たんぱく質などは撮影後にご自身で入力してください。

## スマホにインストール(ホーム画面に追加)

このアプリは PWA(manifest + Service Worker)対応にしてあるので、ホーム画面に追加すると
アイコンタップで直接開ける・オフラインでも動く・ブラウザのアドレスバーが出ない、という
ネイティブアプリに近い見た目で使えます。

### 1. まず公開URLを用意する(初回のみ・手動設定が必要)

GitHub Pages で公開するための Actions ワークフロー(`.github/workflows/deploy-pages.yml`)は
リポジトリに含めていますが、**Pages の公開設定自体はGitHubの管理画面上でしか行えない**ため、
以下だけは手動でお願いします。

1. GitHubでこのリポジトリの **Settings → Pages** を開く
2. 「Build and deployment」の **Source** を **GitHub Actions** に変更
3. このブランチを `main` にマージ(またはmainにpush)すると、Actionsが自動でデプロイします
4. 数分後、`https://<ユーザー名>.github.io/<リポジトリ名>/` でアクセスできるようになります
   (Actionsタブのデプロイログ、またはPages設定画面にURLが表示されます)

### 2. スマホのブラウザでURLを開き、ホーム画面に追加する

**iPhone(Safari)**
1. 公開URLをSafariで開く
2. 下部の共有ボタン(□に↑)をタップ
3. 「ホーム画面に追加」を選択 → 追加

**Android(Chrome)**
1. 公開URLをChromeで開く
2. 右上の「⋮」メニュー、または自動で出る「アプリをインストール」バナーをタップ
3. 「インストール」または「ホーム画面に追加」を選択

追加後はアイコンをタップするだけで、緑のヘッダーとタブバーだけのアプリ画面が
フルスクリーンで開きます。データは引き続きそのブラウザの `localStorage` に保存されるため、
Safari版とChrome版など、開くブラウザ・端末が変わるとデータも別になります(バックアップは
「設定」タブのJSONエクスポート/インポートを使ってください)。

## ファイル構成

```
index.html      画面構成(ダッシュボード/食事/筋トレ/体重/設定の5タブ)
css/style.css   スタイル(ライト/ダークモード自動対応)
js/app.js       ロジック(データ保存・目標計算・グラフ描画など、外部依存なし)
js/sync.js      Google Drive経由の端末間同期(任意機能、要セットアップ)
js/n8n-sync.js  n8n経由の体重自動取り込み(任意機能、要セットアップ)
manifest.json   PWAマニフェスト(アプリ名・アイコン・スタンドアロン表示設定)
sw.js           Service Worker(アプリ本体をオフラインキャッシュ)
icons/          ホーム画面アイコン(192/512/Apple touch icon/favicon)
.github/workflows/deploy-pages.yml  GitHub Pagesへの自動デプロイ
docs/           別プロジェクト(SNS/YouTube自動収集のn8nワークフロー)のドキュメント
```

外部ライブラリやビルドツールには依存していないため、オフラインでもそのまま動作します。
